# Оплата конкурентов и выводы для эквайринга Firestorm

## Контекст

- Проект: `Firestorm`
- Продукт: `Префлоп тренажёр`
- Цель файла: понять, какими способами оплачиваются продукты конкурентов, и использовать это для выбора эквайринга и платёжной архитектуры
- Дата фиксации фактов: `23 марта 2026`

---

## Problem Statement

- Ожидалось: выделить платёжные паттерны конкурентов, чтобы понять, какие способы оплаты обязательны для `Firestorm`.
- Фактически: по конкурентам уже собран базовый продуктовый анализ, но отдельного слоя по оплатам ещё не было.
- Граница задачи: этот документ фиксирует только публично подтверждённые способы оплаты и продуктовые выводы по эквайрингу.

Уверенность: 78% -> 95% — задача сформулирована явно, артефакт создан под конкретное решение по эквайрингу.

## Input

- Уже собраны конкуренты: `FreeBetRange`, `ICMIZER 3`, `PreflopHero MTT`
- Есть публичные страницы магазинов, тарифов и help-документации
- Для `Firestorm` важно выбрать эквайринг и платёжный сценарий
- Не у всех конкурентов прямой checkout прозрачно раскрывает точный PSP

## Output

- Создан единый документ по способам оплаты конкурентов.
- По каждому конкуренту выделены:
- подтверждённые способы оплаты
- точка оплаты
- локальность метода
- наличие ручного платежа
- наличие recurring/subscription логики
- Сформулированы выводы для `Firestorm`.

## Outcome

- Решение по эквайрингу можно принимать не “в вакууме”, а отталкиваясь от рынка.
- Станет понятнее, что является обязательным минимумом, а что дополнительным каналом оплаты.
- Можно обсуждать с Сашей уже не “какой эквайринг нравится”, а “какая платёжная стратегия нужна под рынок”.

## Сводка по рынку

### Общий паттерн

- Конкуренты используют не один универсальный путь оплаты, а комбинацию:
- встроенная онлайн-оплата картой
- локальные методы через партнёрскую витрину
- ручные переводы или альтернативные методы через саппорт
- подписочная логика с автообновлением

### Что уже видно

- Для русскоязычной аудитории сильным преимуществом остаются локальные методы оплаты.
- Для международной аудитории важна быстрая self-service оплата без общения с поддержкой.
- Часть конкурентов держит запасной ручной путь оплаты на случай, если основной checkout неудобен пользователю.

## Конкуренты

### 1. GipsyTeam как платёжная витрина

#### Подтверждённые способы оплаты

- Банковские карты `VISA/MasterCard/МИР`, выпущенные банками РФ
- `СБП`
- `Luxon`
- `GTP` (`GipsyTeam Points`)
- `Яндекс Пэй`
- `T-Pay`
- `Подели` через `Robokassa`

#### Где происходит оплата

- Оплата идёт внутри магазина `GipsyTeam`
- Для иностранных карт магазин направляет на отдельный домен `shop.gipsyteam.com`

#### Важные особенности

- Есть cashback-система в `GTP`
- Есть локальный checkout для РФ-аудитории
- Есть fallback через поддержку, если нужен другой способ оплаты
- Доставка цифрового товара может занимать от нескольких минут до `48` часов в рабочие дни

#### Что это значит для Firestorm

- Локальные методы для русскоязычного рынка критичны.
- `СБП` выглядит не как nice-to-have, а как обязательный способ оплаты.
- Если Firestorm целится в РФ/СНГ-аудиторию, одного “международного card checkout” будет недостаточно.

Уверенность: 90% -> 99% — способы оплаты подтверждены официальными страницами `Оплата и доставка` и `Как сделать покупку`.

### 2. FreeBetRange

#### Подтверждённые способы оплаты

Через собственный checkout:
- встроенный checkout для `Pro/Elite`
- `Crypto` как отдельный способ оплаты в checkout

Через ручную оплату:
- `Skrill`
- `Wise`
- `Binance Pay`
- `BTC`
- `USDT TRC20`

#### Где происходит оплата

- Встроенный checkout внутри продукта при апгрейде до `Pro/Elite`
- Отдельный ручной путь оплаты по реквизитам из help-центра

#### Важные особенности

- Платная лицензия активируется автоматически после обычного checkout
- Крипто-оплата тоже обрабатывается автоматически
- Ручные переводы обрабатываются в течение `24` часов, чаще быстрее
- Подписку можно менять и отменять из `Billing`
- Lifetime-лицензии нет, логика чисто подписочная

#### Что это значит для Firestorm

- Сильный паттерн: основной self-service checkout + запасной ручной канал.
- Крипто у конкурента уже не экзотика, а рабочий альтернативный способ.
- Если мы не готовы сразу давать крипту, минимум нужен встроенный subscription checkout и понятный fallback.

Уверенность: 82% -> 96% — способ оплаты подтверждён help-центром FreeBetRange, включая crypto и manual transfer.

### 3. PreflopHero MTT

#### Подтверждённые способы оплаты

Основной способ:
- оплата банковской картой внутри приложения

Альтернативные способы:
- `Skrill`
- перевод через покер-рум
- контакт с поддержкой через `Skype PreflopHero`

#### Где происходит оплата

- Основной платёжный путь встроен в приложение
- Альтернативные способы запускаются через ручной контакт с поддержкой

#### Важные особенности

- Основной checkout максимально простой по сообщению: “оплата картой в приложении”
- Для нестандартных способов оплаты нет self-service интерфейса
- Платёжная модель построена как подписка `1 месяц / 3 месяца / 1 год`

#### Что это значит для Firestorm

- Карточный checkout остаётся базовым ожиданием пользователя.
- Ручной fallback через саппорт всё ещё используется в нише.
- Но зависимость от ручного саппорта выглядит слабее, чем автоматизированные альтернативы у FreeBetRange.

Уверенность: 80% -> 94% — способы оплаты подтверждены официальной страницей `MTT subscription`.

### 4. ICMIZER 3

#### Подтверждённые способы оплаты

Напрямую подтверждено:
- покупка подписки на официальном сайте через checkout с автообновлением
- банковская карта как легитимный способ оплаты в условиях сервиса

Через GipsyTeam дополнительно доступны:
- карты РФ
- `СБП`
- `Luxon`
- `GTP`
- `Яндекс Пэй`
- `T-Pay`
- `Подели`

#### Где происходит оплата

- На официальном сайте ICMIZER через purchase-flow подписки
- Через GipsyTeam как локальную магазинную витрину

#### Что пока не подтверждено напрямую

- Точный список direct-методов на checkout ICMIZER публично не раскрыт на найденных актуальных страницах
- Нельзя уверенно утверждать наличие `PayPal` или другого конкретного PSP в текущем checkout без прямой проверки страницы оплаты

#### Важные особенности

- Подписка продлевается автоматически
- Есть возврат денег в течение первого месяца для части планов
- У ICMIZER есть и собственный direct checkout, и локальная партнёрская витрина

#### Что это значит для Firestorm

- Для сложного экспертного продукта связка “direct checkout + локальный реселлер/витрина” выглядит жизнеспособной.
- Если у нас будет международная аудитория и СНГ-аудитория одновременно, возможно, стоит проектировать не один канал оплаты, а два.

Уверенность: 62% -> 84% — recurring-модель и card-based оплата подтверждены, но точный набор direct-методов checkout не раскрыт на публичной странице.

## Выводы для выбора эквайринга Firestorm

### 1. Обязательный минимум

Для `Firestorm` как минимум нужны:
- онлайн-оплата банковской картой
- подписочная логика с автопродлением или понятным recurring-сценарием
- ручной fallback-канал оплаты на старте

### 2. Если аудитория РФ/СНГ важна

Тогда желательно сразу иметь:
- `СБП`
- карты РФ
- локальный checkout без зависимости от иностранных карт

Без этого мы будем проигрывать витринам вроде `GipsyTeam` по конверсии и доверию.

### 3. Если аудитория международная

Тогда желательно иметь:
- международный карточный эквайринг
- понятную recurring-модель
- запасной ручной канал для тех, у кого обычная карта не проходит

### 4. Если нужен запасной канал на раннем этапе

Практичный стартовый вариант:
- основной автоматический checkout
- fallback через поддержку
- позже добавить второй слой: крипта или локальные методы

### 5. Что особенно видно по конкурентам

- `СБП` и локальные методы усиливают конверсию в русскоязычном сегменте
- Crypto уже используется как реальный запасной путь, а не как редкая опция
- Ручной способ оплаты всё ещё рабочий, но выглядит слабее, чем автоматизированная альтернатива
- Подписочная модель доминирует над lifetime-моделью

## Предварительная рекомендация для Firestorm

### Если нужна быстрая и практичная конфигурация

Стартовый платёжный стек:
- карточный checkout
- `СБП`
- подписка с автопродлением
- ручной fallback через поддержку

### Если нужна более сильная market-fit конфигурация

Следующий слой:
- локальный эквайринг для РФ
- международный card checkout
- отдельный альтернативный метод для проблемных кейсов: крипта или manual invoice

### Чего бы я не делал

- Не запускал бы продукт только с одним способом оплаты.
- Не делал бы регистрацию и оплату зависимыми от ручного общения, если это основной сценарий.
- Не строил бы checkout только под международные карты, если пользовательский фокус в СНГ.
