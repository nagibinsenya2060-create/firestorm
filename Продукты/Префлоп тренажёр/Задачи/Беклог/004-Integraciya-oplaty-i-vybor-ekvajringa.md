# **004 Оплата тарифов и выбор эквайринга**

## **Problem Statement**

- Ожидалось: пользователь может оплатить выбранный тариф и сразу получить доступ к тренажёру.
- Фактически: платёжный контур и выбранный эквайринг для тренажёра не зафиксированы.
- Граница: путь `выбрал тариф -> оплатил -> получил активный доступ`.

## **Input**

- Есть обязательный этап монетизации перед релизом.
- Есть потребность выбрать эквайринг под целевой рынок.
- Есть страница тарифов как источник выбранного плана.

## **Output**

- Критерии выбора эквайринга зафиксированы.
- Список финальных кандидатов эквайринга собран.
- Эквайринг для релизного запуска выбран.
- Техническая схема платёжной интеграции описана.
- Оплата тарифа через выбранный эквайринг подключена.
- Успешный платёж с активацией доступа реализован.
- Неуспешный платёж с корректным статусом пользователя реализован.
- Возврат пользователя после оплаты в продукт с актуальным доступом реализован.
- Базовые статусы оплат в админ/аналитике фиксируются.

## **Outcome**

- Появляется рабочая монетизация тренажёра.
- Пользователь проходит оплату без ручной поддержки.
- Команда может прогнозировать выручку на основании реальных оплат.

## **Декомпозиция**

### **Этап 1. Выбор эквайринга**

- Критерии выбора эквайринга сформированы.
- Кандидаты по комиссии, доступности и интеграции сравнены.
- Финальный эквайринг согласован.

### **Этап 2. Интеграция платежа**

- Создание платежа для выбранного тарифа реализовано.
- Обработка webhook/статусов платежа реализована.
- Активация/неактивация доступа по результату платежа реализована.

### **Этап 3. Проверка сквозного сценария**

- Сценарий успешной оплаты проверен.
- Сценарий неуспешной оплаты проверен.
- Сценарий возврата в продукт после оплаты проверен.

## **Чеклист проверки**

- [ ] Критерии выбора эквайринга зафиксированы.
- [ ] Финальный эквайринг выбран.
- [ ] Платёжная интеграция подключена.
- [ ] Успешный платёж активирует доступ.
- [ ] Неуспешный платёж не активирует доступ.
- [ ] Возврат пользователя в продукт после оплаты реализован.
- [ ] Базовые статусы платежей фиксируются.

## **Визуальное подтверждение**

- Скриншот 1 (полная ширина): выбор тарифа и переход к оплате.
- Скриншот 2 (полная ширина): успешная оплата и активированный доступ.
- Скриншот 3 (полная ширина): неуспешная оплата и корректный статус.
- Скриншот 4 (полная ширина): возврат в тренажёр после оплаты.
