# Правила по структуре и именованию в Firestorm

## Зачем нужен этот файл

Этот файл фиксирует локальный стандарт работы с папками и файлами внутри проекта `Firestorm`, чтобы новые материалы складывались в правильное место и назывались единообразно.

---

## Базовый принцип

- Корневая папка проекта: `D:\Dovlands\cursor\proect\Firestorm`
- Все новые материалы по проекту `Firestorm` нужно создавать внутри этой папки.
- Нельзя самовольно создавать альтернативные корневые структуры вроде `work-projects/Firestorm`.

---

## Правило по папкам

- Папки внутри `Firestorm` нужно называть по-русски.
- Новые подпапки нужно подстраивать под уже существующую структуру проекта.
- Если в проекте уже существует папка с конкретным названием, нужно использовать именно её.
- Если в существующем названии есть опечатка, нельзя автоматически переименовывать папку без прямого запроса пользователя.

### Текущая фактическая структура

- `Firestorm\Продукты`
- `Firestorm\Созвоны`
- `Firestorm\Продукты\Префлоп тренажёр`
- `Firestorm\Продукты\Префлоп тренажёр\Куонкуренты`

### Что это значит на практике

- Все материалы по продукту `Префлоп тренажёр` нужно складывать в:
- `D:\Dovlands\cursor\proect\Firestorm\Продукты\Префлоп тренажёр`
- Все материалы по конкурентам нужно складывать в:
- `D:\Dovlands\cursor\proect\Firestorm\Продукты\Префлоп тренажёр\Куонкуренты`

---

## Правило по `.md` файлам

- Markdown-файлы нужно называть в транслите латиницей.
- Имена файлов должны быть читаемыми и короткими.
- Для файлов и wiki-страниц, созданных Никитой Нагибиным, использовать префикс автора:
- `Nikita-Nagibin-...`
- Допустимый стиль:
- `Konkurenty.md`
- `Voprosy-dlya-Sashi.md`
- `Segmenty-AJTBD-dlya-Sashi-1h.md`
- `FreeBetRange-GipsyTeam.md`
- `Nikita-Nagibin-TODO-bufer-zadach.md`

### Чего не делать

- Не называть `.md` файлы русскими именами, если нет отдельного запроса.
- Не смешивать русские папки и английские служебные корни.
- Не использовать случайные технические названия файлов без смысла.

---

## Правило по новым материалам

- Сначала нужно найти фактическую папку проекта.
- Потом нужно проверить, в какой русской подпапке уже лежат материалы такого типа.
- Только после этого создавать новый файл.
- Если создаётся новый `.md`, имя должно быть в транслите.

---

## Правило самопроверки перед созданием файла

Перед созданием нового файла в `Firestorm` нужно проверить:

- найден ли фактический корень проекта;
- есть ли уже подходящая русская папка;
- не создаётся ли дублирующая структура;
- соответствует ли имя `.md` транслиту;
- соответствует ли размещение типу материала.

---

## Обязательное поведение дальше

- Для `Firestorm` использовать только фактическую структуру папок внутри `D:\Dovlands\cursor\proect\Firestorm`
- Для папок использовать русский язык
- Для `.md` использовать транслит
- Для новых файлов/страниц Никиты использовать префикс `Nikita-Nagibin-`
- Не повторять старую ошибку с альтернативным корнем `work-projects`
